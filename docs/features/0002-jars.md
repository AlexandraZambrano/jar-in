# 0002 — Jars

- **Status:** 🟡 in progress
- **Phase:** 1
- **Spec refs:** SPEC.md §3, §4; DESIGN-STICKER-SHEET.md §2.3, §3.2
- **Depends on:** 0001

## Goal

The user can see their jars, start from the editable default template
(Essentials 50 / Investment 25 / Safe fund 15 / Joy-jar 10), and
create / rename / re-percentage / retype / recolour jars and delete
them. Jars are the backbone every other Phase 1 feature hangs off.

## User stories

- As a new user, I get a sensible starting set of jars I can immediately
  edit rather than a blank screen.
- As a user, I can add a jar, set its name, percentage, type
  (flow / accumulation), colour, icon and pattern, and for accumulation
  jars a target amount.
- As a user, I can delete a jar I don't want.
- As a user, I can see whether my percentages add up to 100%.

## Acceptance criteria

1. `seed()` creates the four default-template jars with the colours,
   icons and patterns from DESIGN-STICKER-SHEET.md §2.3/§2.4 and
   `order` 0–3.
2. `/jars` lists jars ordered by `order`, each showing icon, name, type
   badge, percentage; total percentage shown with a warning treatment
   when `≠ 100`.
3. `/jars/new` and `/jars/:id` open an editor with: name (required),
   percentage (0–100, 0.5 steps), type (flow / accumulation), colour
   (from the palette), icon (from the icon set), pattern (6 options),
   and — only when type = accumulation — target amount (money input) and
   opening balance.
4. Saving validates: name non-empty, percentage in range, target
   required for accumulation. Invalid fields block save with an inline
   message.
5. Creating/editing/deleting updates the list and the dashboard live
   (RxDB reactivity), with `updatedAt` bumped.
6. Deleting a jar with transactions warns first and, on confirm,
   soft-deletes the jar (transactions are kept, shown as "Unassigned"
   until reassigned — reassignment UI is feature 0005).
7. Sub-categories: the editor can add / rename / reorder / remove a
   jar's sub-category list. (Tagging transactions to them is 0005.)

## Data touched

## Out of scope

analytics (Phase 2), drag-to-reorder jars (nice-to-have, later).
